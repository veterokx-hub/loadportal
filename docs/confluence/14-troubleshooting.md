# Разбор сбоев

Сначала слой: браузер, constructor, orchestrator, GitLab, под генератора, VictoriaMetrics. Ниже симптом и первый файл или лог, не полный чеклист кластера.

## Вход и UI

| Симптом | Куда смотреть |
|---|---|
| Логин 401, пользователя admin нет | Лог constructor на первом старте, строка про bootstrap-пароль. Повторный старт пароль не печатает |
| После логина пускает только на смену пароля | Флаг `must_change_password`. Это норма первого входа |
| Сессия отвалилась, сценарий на месте | TTL 3 часа. Черновик в `localStorage` `ltp-state-v1` |
| Сценарий пропал | Пользователь не сохранял сборку, браузер очистил storage. В БД черновика нет |
| Кнопка «Далее» серая | Здоровье: пустой обязательный параметр или нет запросов. Предупреждение про переменные её не держит |
| Клик по Здоровью не скроллит | В компоненте шага нет обработчика `focus` этой проверки |
| Поле бирюзовое, хотя это «просто имя» | Источник — счётчик или случайная строка, либо это извлечение или CSV. Имя уйдёт в скрипт |
| Два Query с одним именем, предупреждения нет | Так и задумано. Имя Query — ключ HTTP |
| Извлечение `param3` и path с корреляцией `param3`, предупреждения нет | Так и задумано. Path читает переменную, не создаёт вторую |
| «Колонка есть в датасетах», хотя колонка нигде не выбрана | Колонка становится переменной сразу. Если оба датасета попадут в одну группу, JMeter и Gatling оставят одно значение |
| «В Gatling станет …» | В имени цифра в начале или символ вне латиницы и цифр. JMeter и k6 оставят исходное |

## Сборка

| Симптом | Куда смотреть |
|---|---|
| 502 на `/api/builds/save` | constructor `/ready`: какой генератор красный. Токен `X-Internal-Token` одинаковый у вызывающего и генератора |
| Файл скачался, в нём нет запроса | Группировка или пустой path. Сравнить `scenario_json` сборки и то, что ушло в генератор |
| В k6 переменная пустая, в JMeter есть | k6 читает корреляцию из `vars`, колонку из `row`. Имя колонки и имя извлечения совпали: в JMeter это одна переменная, в k6 разные объекты, Здоровье всё равно предупреждает |
| В Gatling `#{...}` пустой, в JMeter значение есть | `_el_ident` переписал имя. Строка Здоровья «в Gatling станет» как раз про это |
| Случайная строка видна как переменная только в Gatling | В JMeter и k6 это функция без имени. Конфликт с таким именем помечается `(Gatling)` |

## Прогон

| Симптом | Куда смотреть |
|---|---|
| Карточка сразу `failed`, пайплайна нет | Orchestrator: нет trigger-token, нет S3, неверный `gitlab/project-id`. Текст в `error_message` |
| Пайплайн есть, дочернего нет | Джоба pre-check. Код 2 — контракт `RUN_SPEC`, код 3 — окружение (образы, квоты, Vault) |
| Родитель красный, `verdict_json` пустой | Smoke не прошёл, либо упало до publish. Вердикта gate не было |
| Родитель зелёный, в портале `failed` | Publish дошёл с `failed` или `invalid`. GitLab оба красит одинаково, причина в `verdict_json` |
| Завис в `running` | Webhook не дошёл или секрет `X-Gitlab-Token` не совпал. Дочерний пайплайн статус сам не присылает |
| Отмена не останавливает под | `gitlab/api-token`. Trigger-токена на cancel не хватает |
| В Grafana пусто при живом JMeter | Нет `LT_INFLUX_URL` на поде |
| В Grafana пусто при живом k6 | Нет `K6_PROMETHEUS_RW_SERVER_URL` |
| В Grafana пусто при живом Gatling | `lt-run` в VictoriaMetrics не пишет. Это не поломка пода |
| Пороги SLA не сработали | Портал их не отправляет. Профиль `load` без блока `sla` |

## Анализ

| Симптом | Куда смотреть |
|---|---|
| Отчёт есть, но это синтетика | Пустой `victoriametrics/url` или `analysis/demo` / галочка демо. Поля `demo`, `demo_fault` |
| Прогон завершился, отчёта нет | Пустые cluster, namespace или service. Автозапуск без них молчит. Либо `analysis/auto-on-finish=false` |
| «Пересчитать» не меняет старый отчёт | Создаётся новая строка. Старая остаётся со своей `ruleset_version` |
| Метрики сервиса есть, вердикт прогона пустой | Это разные расчёты. Вердикт прогона — файлы на поде, не VictoriaMetrics |

## База и выкладка

| Симптом | Куда смотреть |
|---|---|
| Pod constructor CrashLoop, validate failed | Init-job не прошёл или схема правилась руками |
| После деплоя UI ходит на старый API | Frontend не пересобран, либо Ingress обошёл Next и бьёт в старый Service |
| CORS в браузере, curl с пода ок | `allowed-origins` не равен Origin из DevTools |
| История сборок внезапно поредела | Cron 03:15, TTL 30 дней, лимит 30 на пользователя |

## Как приложить улику к задаче

Для бага сценария: `GET /api/builds/{id}/scenario` и скачанный скрипт. Для бага прогона: `run_id`, `gitlab_pipeline_id`, `verdict_json`, `error_message`. Для бага анализа: `analysis_id`, `request_json`, `demo`. Пароли, токены и тела с боевыми данными в задачу не класть.
