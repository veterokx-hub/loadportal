# Продукт

Портал готовит сценарий нагрузочного теста, собирает скрипт под один из трёх движков и запускает прогон через GitLab CI. После прогона по метрикам VictoriaMetrics строится отчёт: вердикт, гипотезы, цепочки «причина → следствие».

Короткое имя в интерфейсе: **НТ · Портал**.

## Для кого

| Роль | Что делает в портале |
|---|---|
| Инженер НТ | Импортирует OpenAPI или Postman, правит запросы, параметры, интенсивность, сохраняет сборку, скачивает скрипт, запускает прогон |
| Разработчик сервиса | Смотрит отчёт анализа: куда смотреть в коде, какой запрос MetricsQL перепроверить |
| Сопровождение портала | Держит constructor, orchestrator, генераторы, Postgres, секреты GitLab и S3, webhook |
| Администратор | Пользователи, первый пароль admin, LDAP если включён |

## Что продукт делает и чего не делает

Делает:

- разбор OpenAPI и Postman в черновик сценария;
- ручной сценарий с пустого листа;
- параметры, извлечения, CSV, интенсивность, AutoStop;
- сборку JMeter `.jmx`, k6 и Gatling zip;
- историю сборок пользователя;
- запуск через GitLab: скрипт в S3, trigger, webhook статуса и вердикта;
- анализ окна метрик по прогону, ссылке Grafana или ручной цели.

Не делает:

- не разворачивает стенд (модуль «Стенд» — заглушка);
- не публикует PDF и страницу в Confluence (модуль «Отчёт» — заглушка);
- не считает quality gate по VictoriaMetrics. Вердикт пайплайна считается по файлам на поде генератора;
- не хранит k8s-манифесты. Обновление в кластере — Argo CD по тегу образа, вне этого репозитория.

## Модули интерфейса

| Модуль | URL | Состояние |
|---|---|---|
| Сценарий | `/scenario/source`, `requests`, `correlation`, `intensity` | Рабочий |
| Стенд | `/environment` | Заглушка |
| Запуск | `/run/new`, `/run/list`, `/run/{id}` | Карточки и trigger есть. Прогон доходит до конца только при настроенных GitLab, S3 и webhook |
| Анализ | `/analysis/new`, `/analysis/list`, `/analysis/{id}` | Рабочий. Без VictoriaMetrics показывает синтетику |
| Отчёт | `/report` | Заглушка |

Код доступности: `frontend/lib/modules.ts`, поле `available`.

## Движки

Один сценарий, три сборки. Движок выбирается на шаге «Интенсивность и сборка».

| Движок | Артефакт |
|---|---|
| JMeter | `.jmx` |
| k6 | скрипт или zip |
| Gatling | zip Maven-проекта с `PortalSimulation.java` |

Модель сценария от движка не зависит. Отличия появляются только в генераторе. См. [Переменные скрипта](05-script-variables.md).

## Окружение

Один прод-экземпляр в тестовом k8s-кластере. Локально тот же состав поднимается `docker compose`. Consul и Vault локально выключены, пока их не включают переменными и `config/platform.properties`.
