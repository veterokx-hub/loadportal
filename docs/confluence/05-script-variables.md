# Переменные скрипта

Имя в форме и переменная в JMeter, k6 или Gatling — разные вещи. Путаница здесь даёт ложные предупреждения в Здоровье и затёртые значения на прогоне.

Код решения, что считать переменной: `frontend/lib/script-vars.ts`. Генераторы: `JmxBuilder.java`, `k6_generator.py`, `gatling_generator.py`.

## Что остаётся только в портале

| Сущность | Куда девается имя |
|---|---|
| Имя Query, Header | Ключ HTTP. Переменной нет |
| Имя Path, Body | Плейсхолдер `{имя}`. В запрос подставляется значение |
| Константа | Текст. Если внутри есть `${var}`, движок прочитает уже существующую переменную |
| UUID, случайное число, метка времени | Функция на месте вызова, отдельного имени нет |

## Что становится переменной

| Сущность | Имя в скрипте | Движки |
|---|---|---|
| Извлечение | `variable` | все три |
| Колонка датасета | заголовок колонки | JMeter и Gatling создают переменную на каждую колонку привязанного датасета. k6 кладёт колонки в объект `row` |
| Счётчик | имя параметра | все три |
| Случайная строка | имя параметра | только Gatling (`session.set`). В JMeter и k6 это функция без имени |
| Корреляция | не создаёт имя | читает `source.variable` |

Два параметра с корреляцией на одну и ту же переменную — два чтения. Предупреждения из-за этого нет.

Извлечение `param3` и path ниже, у которого источник «Корреляция» и переменная `param3`, — одна переменная. Здоровье это не считает повтором.

Повтор есть, когда одно имя пишут двое:

- два извлечения;
- колонка и извлечение;
- колонка и счётчик;
- две колонки с одним заголовком в одном датасете;
- одна и та же колонка в двух датасетах;
- случайная строка Gatling и любое другое имя из таблицы выше — конфликт только в Gatling, в тексте Здоровья стоит `(Gatling)`.

Колонки попадают в сравнение сразу после появления датасета, даже если ни один параметр их ещё не выбрал. Два CSV с одинаковым заголовком подсвечиваются всегда: если оба датасета окажутся в одной группе, JMeter и Gatling оставят одно значение.

## Ограничение ввода

В поле извлечения, в имени счётчика и случайной строки, в заголовке CSV допускаются латинские буквы и цифры. Заголовок CSV чистится при уходе из поля и при загрузке файла. Значения строк CSV не чистятся.

Имя с цифры в начале Gatling переписывает: `1a` → `v_1a`. Дефис и прочие символы Gatling выкидывает: `user-id` → `userid`. JMeter и k6 оставляют исходное имя. Здоровье пишет: имя в Gatling станет другим, с пометкой `(Gatling)`.

Подчёркивание движки принимают. Новые поля его не дают ввести, чтобы имя не разъехалось с правилом «только буквы и цифры».

Поля, чьё имя уходит в скрипт, в UI с бирюзовой подложкой. Обычное имя Query такой подложки не имеет, пока источник не счётчик и не случайная строка.

## Как это лежит в каждом движке

JMeter:

- извлечение — `refname` постпроцессора;
- корреляция — текст `${variable}`;
- CSV Data Set — `variableNames` равен всем колонкам;
- счётчик — `CounterConfig` с именем параметра, ссылка `${имя}`;
- `{name}` в path и body заменяется на отрисованное значение первого параметра с этим именем.

k6:

- извлечение пишет `vars[variable]`;
- корреляция читает `vars[variable]`;
- CSV-параметр читает `row[колонка]`;
- счётчик — ключ в `__counters`, не поле `vars`;
- `${…}` в константе резолвится сначала из `vars`, потом из `row`.

Gatling:

- фидер `csv()` кладёт в сессию каждую колонку под заголовком, один `.feed` на итерацию группы;
- корреляция — `#{variable}` после очистки идентификатора;
- извлечение — `saveAs`;
- счётчик — фидер `GENERATED_VALUES` под именем параметра;
- случайная строка — `session.set(имя параметра, …)` перед HTTP.

## Куда смотреть, если значения затёрлись

1. Здоровье: строка «задаётся несколько раз» или «колонка есть в датасетах».
2. Одинаковый заголовок в двух датасетах одной группы. В Gatling фидеры идут подряд, второй затирает атрибут. В JMeter второй CSV Data Set затирает переменную.
3. Счётчик и извлечение с одним именем. В JMeter это один `${name}`.
4. Имя с дефисом: в Gatling переменная уже другая, корреляция `#{user-id}` её не найдёт.
